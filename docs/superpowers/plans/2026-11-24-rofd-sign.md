# rofd 签章、验签与保真存盘 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 rofd 能验签、能签章，并且带签章的文件加批注存盘后章仍然有效。

**Architecture:** io 对签章结构只做只读投影、原字节透传，并新增保真存盘（只重写批注条目）；render 把章画在 body 之后；新 crate `rofd-sign` 承担密码学（SM2/SM3、SES 编解码、证书文件）和验签、签章的字节级 API；component 提供模态的签章状态，三个适配器只做转发，三个示例应用做完整流程。

**Tech Stack:** Rust（workspace 钉 1.98.1），quick-xml 0.36，zip 2.2，image 0.25，RustCrypto `sm3` 0.5 与 `sm2` 0.14，`keystore-pkcs12` 1（Task 14 的 spike 把关），Vue 3 + ant-design-vue（web-app），gpui-pre 0.3.10（gpui-app），xilem（xilem-app）。

**Spec:** `docs/superpowers/specs/2026-11-23-rofd-sign-design.md`。下文的 U / M / I 编号都指它。

**Execution notes:** 在 `main` 上直接提交（AGENTS 规则 9）；执行方式为 native，在本会话内联执行。

## Global Constraints

- 库内绝不读系统时间：签章时间与有效期判断的时间由宿主注入（spec I 系列之外的仓库规则 4）。
- 代码注释与 commit message 一律英文；代码的注释、标识符、文件名里不出现 WPS 字样；中文只用于设计文档和面向用户的 UI 文案。
- `rofd-dom` 与 `rofd-io` 是 rword 的跨仓承诺面：只做加法。`write_ofd` 与 `write_ofd_with_text_layout` 的签名和语义不变；不修改 rword 仓库。
- 新 crate 声明 `rust-version = "1.96"`。`rofd-sign` 及以下不依赖平台 crate，必须能在 `wasm32-unknown-unknown` 上编译。
- 依赖许可必须在 `deny.toml` 的允许列表内。
- 每个任务收尾前跑：`cargo fmt --all`、`cargo clippy --workspace --all-targets -- -D warnings`、本任务的测试。改了 io 存盘逻辑后 `cargo test -p rofd-io write_fidelity` 必须绿。
- 一个任务一次 commit，conventional commits，英文。
- 未得到用户答复的四件事按默认处理（spec §16）：SES v5 维持报“暂不支持”；ofd-h-platform 的 BJCA 样例不入库，需要时写成本地 `#[ignore]` 测试；不动 rword；WPS 人工验收留成清单交给用户。

## Review Focus

1. 厂商写法的签章：相对 BaseLoc、`MaxSignId` 为 `s1`、多个 StampAnnot 同 ID、References 一直列到资源文件。解析与验签不得失败或误报。钉在 Task 7 `vendor_style_signature_parses` 与 Task 11 `vendor_style_references_verify_integrity`。
2. `SignedValue.dat` 或 `Seal.esl` 的 DER 损坏、截断。该签名的验签结果应为 Unparseable，文档照常打开并告警。钉在 Task 7 `corrupt_seal_still_opens_with_warning` 与 Task 11 `truncated_signed_value_is_unparseable`。
3. 包里带目录条目、条目顺序特殊的 zip。保真存盘不丢条目、不崩。钉在 Task 3 `directory_entries_survive_preserving_save`。
4. 证书文件口令错误，或私钥不是 SM2。返回明确的 `SignError`，不 panic。钉在 Task 14 `wrong_password_and_non_sm2_key_are_errors`。
5. 预留段用尽，或已签章文件没有批注入口却要写入批注。返回可观测的结果，不静默。钉在 Task 3 的 `reserve_exhausted_is_reported` 与 `signed_without_annotation_entry_is_blocked`。

```rust
pub enum DocumentXmlChange { Generated, Untouched, MaxUnitId, AnnotationsLocInserted }

pub struct Preserved {
    pub bytes: Vec<u8>,
    pub document_xml: DocumentXmlChange,
    pub full_write_fallback: bool,
    pub blocked_by_signature: bool,
    pub reserve_exhausted: bool,
}

/// 编辑器存盘的唯一入口。有原包走保真存盘，没有原包走全量生成。
/// 未签章文件补丁找不到锚点时退回全量写。
pub fn save_ofd(
    doc: &OfdDocument,
    package: Option<&PackageHandle>,
    text_layout: &TextLayoutHints,
) -> Result<Preserved, OfdError>;

/// 保真存盘本体。入参不含 body（I6）。page_ids 是文档顺序的页 ID。
pub fn write_ofd_preserving(
    package: &PackageHandle,
    page_ids: &[PageId],
    annotations: &AnnotationModel,
    id_seed: u64,
    text_layout: &TextLayoutHints,
) -> Result<Preserved, PreserveError>;

pub enum PreserveError {
    PatchAnchorMissing { entry: &'static str, reason: &'static str },
    Io(#[from] OfdError),
}
```

- 另加 `serialize::annotation_entry::serialize_annotations_entry_with(pages: &[(PageId, String)]) -> String`，第二个字段是相对清单目录的 FileLoc。

`write_ofd_preserving` 的步骤：

1. 条目表从 `package.entries` 原样起步，保留原顺序与原字节。
2. 有批注的页按 `page_ids` 顺序确定。用 `serialize_page_annot` 逐页生成批注 XML，ID 分配器从 `id_seed` 起；全部生成后的计数器就是最终 ID。
3. 批注清单路径取 `package.annotations_entry`；没有则取“文档入口所在目录加 `Annots/Annotations.xml`”。
4. 页批注文件的路径：原清单里有的沿用原名；没有的取“清单目录加 `Page_{页序号}/Annotation.xml`”，与现有条目撞名时在文件名后追加 `_rofd`。原来有文件、现在批注被删空的页，保留文件并写成空的 PageAnnot，清单条目也保留。
5. 未签章文件：按值判定补 MaxUnitID；需要清单而没有批注入口时插入入口。任一锚点缺失返回 `PatchAnchorMissing`。
6. 已签章文件：Document.xml 与 OFD.xml 不动。有批注要写而没有批注入口时 `blocked_by_signature` 为 true，此时条目表就是原包。最终 ID 大于 Document.xml 里的 MaxUnitID 时 `reserve_exhausted` 为 true。
7. 用 `write_zip` 写出。

流程：

1. `parse_ofd` 得到模型与原包；读出原包的全部条目。
2. **base** 就是原包条目，只有文件未签章时补三处脚手架，批注条目一律不动：
   - Document.xml 的 MaxUnitID 抬到“原值与 `object_id_seed` 的较大者加 `SIGNATURE_ID_RESERVE`”。
   - 没有批注入口时插入入口，并加一个空清单条目 `Annots/Annotations.xml`。
   - OFD.xml 插入 `<ofd:Signatures>`，指向 `Signs/Signatures.xml`。
   - 任一补丁找不到锚点是 `SignError::Encode`。已签章文件三处都不动。
3. **References** 按 I4：base 里除签章清单、签章目录下的条目、批注清单与批注文件之外的全部条目，路径排序，外加本签名的 `Seal.esl`（有图时）。
4. **落位**：`Pages::Last` 取最后一页，`Pages::All` 取每一页。x 为页宽减 right 再减章宽，y 为页高减 bottom 再减章高，都加上页物理框的原点。任一值为负是 `SignError::InvalidInput`。章的边长：长边为 `size_mm`，短边按像素比例。用户图片统一转成 RGBA 后重新编码为 PNG。
5. **ID** 按 spec §10.2 第 5 步；非数字的 `Signature@ID` 不参与取最大值。
6. **有图**：两轮签名。先 `build_e_seal_info` 交签名方，`finish_seal` 得到 `Seal.esl`；再算 dataHash、`build_tbs` 交签名方，`finish_signature` 得到 `SignedValue.dat`。**无图**：一轮，对 SM3(Signature.xml) 签名后 `build_signed_data`。
7. `Signatures.xml` 整个重写：原有个数逐条原样保留（ID、Type、BaseLoc 用文件里的原值），追加新条目，MaxSignId 取最大的数字 ID；原来是非数字的 MaxSignId 且没有数字 ID 时保留原值。
8. 组包：base 加签章清单加 `Sign_{n}` 下的文件，n 取最小的未用序号。

## Phase F：示例应用

三个应用的行为相同，列在这里，各任务只写落点。

- **签章对话框**：证书下拉（列证书库，另有“导入证书…”）；章图（内置若干张，另有“选择图片…”，以及“不使用章图”）；“自动盖章”勾选，勾上出现“距右边”“距底部”（默认 10）和“最后一页”勾选（默认勾上）。
- **确定之后**：先用口令校验证书，失败留在对话框并提示。`SignRequest::signs_directly()` 为 true 就直接签；否则进入签章状态等左键。签完把字节写回文件（没有路径就走另存为；浏览器走下载），重开文档，重新验签。
- **状态栏**：没有签章不显示；有签章显示“签章：全部有效（N）”“签章：有失效（a/b）”“签章：仅未验证（N）”之一，可点击。点击弹出详情：逐条签名一节，含章缩略图（无图显示“电子签名”）、签章人、时间、提供者、三层结果、证书的颁发者 / 序列号 / 有效期，以及脚注“未验证证书链与吊销状态”。
- **存盘预检**：先算候选字节。受阻（`blocked_by_signature`）时提示“该文件没有批注入口，保存会使签章失效”，确认后改走全量写。否则对候选字节验签，`newly_invalidated` 非空时提示“保存后 N 个签章将失效”，确认才写盘。
- **证书库**：`CertificateStore` 的 `to_bytes` 结果落本地。桌面放应用数据目录下的 `rofd/certificates.json`（Windows 取 `LOCALAPPDATA`，其他平台取 `HOME/.config`，取不到用临时目录）；web 放 IndexedDB。
- **内置章图**：三张 PNG（圆章、方章、条章），用 `image` crate 画简单图形生成一次后作为静态文件入库。
- 签章时间的 `now` 由宿主取系统时间后格式化成 `YYYY-MM-DD HH:mm:ss` 传入；库内不取时间。
