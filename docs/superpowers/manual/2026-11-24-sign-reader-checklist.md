## 1. 环境与准备

- 一台装了 **WPS**（带签章 / 电子签名功能）的 Windows 机器，能同时构建 rofd
  （Rust 工具链、Node、`D:/code/fonts` 联接，见 `docs/agents/commands.md`）。
- 证书：
  - 开发用：ofdrw 的测试证书 `crates/sign/tests/fixtures/USER.p12`，口令 `777777`
    （仅测试用，不是真实 CA）。
  - **正式验收请再备一份真实 CA 签发的 SM2 证书文件（pfx / p12）及其口令**——国内 CA
    的证书文件布局各异的兼容性只有真实文件能验证（设计 §16 的已知风险）。

生成验收文件（库的样例 `sign_file`，时间由命令行传入；输出后自验并打印每条签名的结论）：

```bash
S=crates/web-app/public/seals
E="cargo run -q -p rofd-sign --features test-ca --example sign_file --"      # 用测试 CA 签
P="cargo run -q -p rofd-sign --example sign_file --"                        # 用证书文件签
SRC=test/ru-yuan-ji-lu.ofd            # 任意一份未签章的 OFD（多页更能看出每页盖章）

$E $SRC target/W1-seal.ofd      --now "2026-11-24 10:30:00" --seal $S/round.png
$P $SRC target/W1-real-cert.ofd --now "2026-11-24 10:30:00" --seal $S/round.png \
      --pfx <真实证书.pfx> --password <口令>
$E $SRC target/W2-all-pages.ofd --now "2026-11-24 10:30:00" --seal $S/round.png --all-pages
$E $SRC target/W3-no-seal.ofd   --now "2026-11-24 10:30:00" --no-seal
$E target/W1-seal.ofd target/W4-annotated.ofd --now "2026-11-24 10:30:31" --no-seal --annotate 3
```

三个样例应用的启动命令（仓库根目录）：

```bash
cd crates/web-app && npm run dev              # 浏览器打开终端打印的地址（WebGPU；无 GPU 自动 CPU 回退）
cargo run -p xilem-app -- target/W1-seal.ofd  # xilem 原生宿主
cargo run -p gpui-app  -- target/W1-seal.ofd  # gpui 原生宿主
```

> 说明：原生两个宿主的签章界面在本次开发中只做了流程与绘制层面的自动化测试，开发机的屏幕
> 处于锁定状态，没有做过目检——下面 §4 的逐项目检是它们**第一次**目检，发现问题照常记。

## 2. 阅读器验收（W1–W5b）

每项都做两件事：**WPS 里看现象**，以及**需要时用 rofd 再开一次看状态栏**。

| 编号 | 操作 | 预期 |
|---|---|---|
| **W1** | 用 WPS 打开 `W1-seal.ofd`，用它的签章 / 验签功能检查 | 最后一页右下角能看见章（圆章，约 40 mm 见方，距右、距底各约 10 mm）；WPS 报签章有效；签章人显示证书的主体（测试证书为 `Test Certificate` 之类） |
| **W1b** | 同上，打开 `W1-real-cert.ofd` | 同 W1，签章人为真实证书的主体。若 WPS 报无效或打不开章，记下证书文件的来源与 WPS 的原话 |
| **W2** | 打开 `W2-all-pages.ofd` | 每一页右下角都有章；每一页的章都验签通过 |
| **W3** | 打开 `W3-no-seal.ofd` | WPS 的签名面板里有**一条签名记录**且验签通过；页面上**没有**章图。若 WPS 不认（面板为空或报无效），逐字记下现象——这决定是否启用设计 M10 的回退分支（退到没有外观的签章） |
| **W4** | 打开 `W4-annotated.ofd`（rofd 签章后加了 3 条红色方框批注并用编辑器的存盘方式保存） | WPS 验签仍全部通过；左上角能看见那 3 个红框批注 |
| **W5** | 用 WPS 打开 `W1-seal.ofd`，在 WPS 里加 2–3 条批注并**保存**，然后做 §3 的观察点，再用 rofd 打开 | WPS 不报 ID 冲突、不报文件损坏；保存后 WPS 再验签的结果如实记录（WPS 保存会不会重写受保护文件不在 rofd 控制范围内，记录即可）；rofd 再打开时能看见 WPS 加的批注，rofd 状态栏的签章结论如实记录 |
| **W5b** | 用 rofd 应用打开 ofdrw 的样例 `crates/sign/tests/fixtures/SESV4SignDoc.ofd`（别家工具签的、**没有批注入口**的已签章文件），加一条批注，保存 | rofd **先弹确认**"保存会使签章失效"；选"取消"则文件不变、文档仍是未保存；选"仍然保存"后文件被全量重写。再用 WPS 打开保存后的文件：如实记录 WPS 是否报签章失效、是否报 ID 冲突（这类文件没有 ID 预留段，是设计 M14 的已知限制） |

## 3. 观察点：MaxUnitID 预留段遇到 WPS

rofd 签章时把 Document.xml 的 `MaxUnitID` 抬高了 65 536（预留段），所以签后 rofd 自己加的
批注 ID 都落在段内、Document.xml 不用改。**WPS 加批注时怎么取号**是这套设计里 rofd 一侧
无法验证的假设，W5 保存后请看三样东西（任选 zip 工具解包，或 `unzip -p <文件> Doc_0/Document.xml`）：

1. **Document.xml 的 `MaxUnitID`**：WPS 保存后是否仍是签章时的值（`原值 + 65536`），还是被改写。
   - 若被改写：WPS 的保存会重写 Document.xml，签章在 WPS 一侧就会失效——这是 WPS 的行为，
     记录即可（WPS 保存自己的文件时如何保持自己的签章有效，不在本次范围）。
2. **WPS 新批注的 ID**：解包看批注文件里的 `ID="…"`。预期在 `MaxUnitID + 1` 以上
   （即 65 546 以上的某个数），不与 rofd 的批注 ID（从"已知最大 ID + 1"起，通常是个小得多的数）重复。
3. **再用 rofd 打开并加一条批注、保存**：rofd 的新批注 ID 从"模型已知的最大已用 ID + 1"起，
   即在 WPS 的最大 ID 之上——确认文件里**没有任何重复的对象 ID**，状态栏不出现"预留段用完"。

可选的重复 ID 检查（解包后）：

```bash
unzip -o -q 文件.ofd -d /tmp/ofd-check
grep -rhoE --exclude-dir=Signs 'ID="[0-9]+"' /tmp/ofd-check/Doc_0 | sort | uniq -d   # 无输出 = 没有重复（签章 ID 是独立编号空间，排除 Signs）
```

## 4. 三个样例应用的签章界面目检

自动化只到"流程走通、面板画得出来"，下面这些是**视觉与手感**，每项在三个应用里各做一遍
（证书用 `USER.p12` / `777777` 导入）：

- [x] 点"签章"弹出对话框：证书下拉、口令、章图（内置三张 + 选择图片 + 不使用章图）、自动盖章。
- [x] 口令输错点确定：**留在对话框**并提示"证书口令错误"；改对后能继续。
- [x] 不选证书 / 不输口令点确定：有对应提示，不崩。
- [x] 选内置圆章、不勾自动盖章、确定：对话框关闭，**章随鼠标移动**（半透明），滚动、缩放照常。
- [x] 左键落在页面上：章固定在鼠标处（整枚在页内；在四个角附近点也整枚可见），随即完成签章；
      状态栏出现"签章：全部有效（N）"，文档标为**未保存**（签章后不写文件）；
      保存（Ctrl+S）之后再次打开文件能看见章。
- [x] 签章前后视图不动（2026-11-24 补）：滚到多页文档的第二页再签章，签完仍停在第二页，章就在眼前
      （不跳回第一页）；签之前选中的批注仍被选中，撤销仍可用（签章不进撤销）。
- [ ] Esc 或右键：取消落位，回到原工具，提示"已取消签章"。
- [x] 落位过程中点击已有批注：不选中、不编辑它。
- [x] 勾选自动盖章：出现距右边 / 距底部 / 最后一页；勾"每一页"后每一页都有章。
- [x] 选"不使用章图"：直接完成电子签名，页面上没有章；详情面板写"电子签名"。
- [x] 状态栏：未签章文件不显示签章条目；签章文件显示"签章：全部有效（N）"；点击弹出详情。
- [x] 详情面板：章缩略图（无图显示"电子签名" / "无章图"）、签章人、时间、提供者、文件完整性 /
      印章一致性 / 签名值三行、颁发者 / 序列号 / 有效期，脚注"未验证证书链与吊销状态"。
- [x] 证书导入后**重启应用**，证书仍在列表里（证书库落盘）。
- [x] 存盘预检：对没有批注入口的已签章文件（ofdrw 样例）加批注后保存——弹"保存会使签章失效"；
      对 rofd 自己签的文件加批注后保存——**不打扰**，直接保存，状态栏仍"全部有效"。
- [x] 对没有批注入口、又带着批注的已签章文件点"签章"（样例 `crates/sign/tests/fixtures/SESV4SignDocAnnotated.ofd`）：
      **被拒绝**，提示"该文件没有批注入口，编辑中的批注无法签进文件：请先处理保存"，文件不变。
- [x] 导入一个读不出来的证书文件（任意改名的文本文件）：提示"证书文件无法使用"，**不是**"证书口令错误"。
- [x] 详情面板的"文件完整性"：对清单外的签名一律能显示；若遇到"失效（该签名未保护任何文件）"，记下样例。

web 端额外两条：

- [x] 无 WebGPU 的浏览器（或关掉硬件加速）走 CPU 回退：落位预览照常显示（半透明）、不白屏、
      控制台没有 `panicked at` / `RuntimeError: unreachable`。
- [x] 签章完成后**不下载**：页面上能看到章，状态栏显示"签章：全部有效（1）"和"签章未保存"；
      按 Ctrl+S 保存之后才下载 `document.ofd`，"签章未保存"消失。

## 5. 已知会出现的现象（不算失败）

- WPS 对 `crates/sign/tests/fixtures/DigitalSign.ofd`（ofdrw 的裸 r/s 数字签名样例，证书在带外）
  的处理不在本次范围。
- rofd 自己不验证证书链与吊销状态，详情面板固定有这条脚注；WPS 若因证书不受信而提示，
  属于预期。
- 用测试 CA（`--features test-ca` 的 `sign_file` 默认分支）签出的文件，证书是自签的——WPS 可能
  提示证书不受信；W1b 用真实证书再验一次就是为了排除这一层。
